# Blockpot Frontend — Architecture (v2.x)

Reference document for agents working on this codebase. Describes the **v2 LGO frontend** after the protocol-alignment refactor and the subsequent KYC / responsible-gaming / EUR-minor accounting work. Organized as skimmable sections with authoritative paths.

---

## 1. Overview

Blockpot is a licensed prize draw operator, powered by Unipot Protocol. This repo is **Blockpot's own Licensed Gaming Operator (LGO) frontend**, connecting wallet-connected players to neutral, immutable prize-draw protocol contracts deployed separately. The stack spans two contract repos:
- `../unipot-contracts` — neutral protocol (Lottery, FundsManager, ComplianceRegistry, WETH)
- `../blockpot-contracts` — LGO-owned contracts (LGO proxy, PlayerRegistry, KycRegistry)

The v2 protocol is deliberately minimal: no token, no governance, no staking, no protocol-level referrals (referrals exist at the operator layer via the LGO's ReferralManager), no operator-collected protocol fees in the Draw core itself. Entries must flow through an LGO proxy contract that is whitelisted in `ComplianceRegistry`; the LGO is the on-chain entry beneficiary, fee collector, and player gate. This frontend is Blockpot's licensed operator; future third-party LGOs can deploy their own LGO + frontend against the same protocol.

Beyond the v2 protocol baseline, the frontend now hosts a full **regulated-operator surface**:
- KYC ladder (T0–T4) with a per-tier required-gates bitmap and EUR-minor wager / single-win thresholds (`KYCRegistry.activePolicy`)
- SumSub IDV via `@sumsub/websdk`, hosted at `/verify`
- Responsible-gaming controls (loss limits, self-exclusion) at `/responsible-gaming`
- Player session backed by SIWE + a Bearer-token gaming service (`VITE_GAMING_SERVICE_URL`)
- Pre-tx deposit/wager evaluator that can route the user to `/verify` before any wallet prompt

**Tech stack:**
- **Build / framework:** Vite 7 + React 19 (TypeScript strict, SPA)
- **Routing:** TanStack Router — file-based under `src/routes/`, `routeTree.gen.ts` regenerated by `@tanstack/router-plugin/vite` on dev/build (gitignored)
- **Data layer:** TanStack Query v5 with IndexedDB persistence + Query Devtools
- **Web3:** wagmi 3 + viem 2
- **KYC:** `@sumsub/websdk@2.6.0`
- **Attestation pinning:** `@web3-storage/w3up-client`
- **Rich text / docs:** TipTap 3 (used by attestation / T&C surfaces)
- **Charts:** recharts 3 + chart.js 4 (transparency surfaces)
- **Styling:** TailwindCSS v4 + CVA + `@blockpot-dev/block-pot-design-system@^0.2.3`
- **Dev tooling:** Storybook 10, ESLint 9 (flat config), TypeScript 5.9

## 3. Routing

File-based TanStack Router. `src/routeTree.gen.ts` is regenerated automatically by `@tanstack/router-plugin/vite` on dev/build (not checked in).

```
src/routes/
├── __root.tsx              # Provider stack, shell, banners, <Outlet/>
├── index.tsx               # /                    → redirects to /play
├── play.tsx                # /play
├── transparency.tsx        # /transparency
├── how-to-play.tsx         # /how-to-play
├── responsible-gaming.tsx  # /responsible-gaming  → ResponsibleGamingPanel
└── verify.tsx              # /verify              → KYC verification flow
```

`/play`, `/transparency`, and `/responsible-gaming` lazy-load their leaf component; `/how-to-play` and `/verify` mount inline. Earn, referrals, and governance routes were removed in the v2 refactor.

`/verify` parses two search params with strict whitelisting:
- `tier?: 'T0' | 'T1' | 'T2' | 'T3' | 'T4'` — target tier; falls back to `T1`. The pre-tx KYC gate populates this from `usePlayerActivityState().state.nextWagerThreshold.tier`.
- `returnTo?: string` — restricted to `['/play']` so a malicious referrer cannot bounce the player to an arbitrary URL after verification.

The route gates the SumSub host on (1) connected wallet, (2) live SIWE session — if either is missing it shows a sign-in CTA via `useSiweSignature()` before mounting `KycVerificationView`.

## 4. Provider stack (`src/routes/__root.tsx`)

From outer to inner:

1. `CountryProvider` — geolocation / region gating
2. `QueryClientProvider` — TanStack Query client + IndexedDB persister (`v6` buster, 1h stale/gc), Query Devtools, restore-time invalidation of `drawState`, `currentRoundEntryIndexes`, `roundPurchases`, `specificRound`
3. `Web3Provider` — wagmi config, chains, connectors; short-circuits to a full-page `OperatorConfigError` if `VITE_OPERATOR_ADDRESS` is invalid
4. `Web3ConnectionProvider` — connection state wrapper
5. `PlayerSessionProvider` — SIWE / Bearer-token session for the connected wallet; mirrors token state into `src/api/gamingServiceClient.ts` so synchronous helpers (e.g. `evaluatePretxDeposit`) can read it without subscribing to context
6. `<SessionExpiryRecovery/>` — sibling component (not a wrapper); subscribes to expiry events from the gaming-service client and re-prompts SIWE
7. `SessionSignalProvider` — fingerprint + behavioral session signals (one POST per session per route to `/v1/session/signal`); exports `recordEntryCadence()` for the entry path
8. `TransactionsProvider` — tx lifecycle tracking, Sonner toasts, `localStorage` history keyed by chainId
9. `SelectedGameProvider` — `main` ↔ `quick` game toggle (quick game contract addresses populated; UI unwired)
10. `ModalOpenStateProvider` — modal open/close bindings (drawSummary, prizesOverview, previousRounds, walletOptions, missedDraw)
11. `BlockpotEventsProvider` — contract event subscriptions (see §10)
12. `BlockpotProvider` — current round / drawn round / view round state (`useDraw`, `useDrawHash`, `useIsDrawingNumbers`, `useViewRoundIndex`)
13. `MissedDrawProvider` — tracks rounds the user missed
14. `LotteryProvider` — round pagination only (`useLoadedRoundIndexes`); narrowed from v1 aggregator
15. `BlockpotDrawProvider` — draw animation state (`useBlockpotDraw`)

Inside the shell, directly below `<Header/>`: `<LGOWhitelistBanner/>` then `<SelfExclusionBanner/>` — both render `null` in the happy path and a blocking banner otherwise. `<Modals/>` mounts inside `BlockpotDrawProvider`; `<UnsupportedRegionDialog/>` mounts inside `CountryProvider` but outside `QueryClientProvider`. Outside everything: `<Toaster/>` from Sonner and a dev-only `<TanStackRouterDevtools/>`.

`<Modals/>` itself renders only `WalletOptionsDialog` and `MissedDrawDialog` today. `DrawSummaryDialog`, `PrizesOverviewDialog`, and the previous-rounds panel are toggled from inside individual feature surfaces (e.g. `Play`), not the global Modals component — `ModalOpenStateProvider` still owns their open-state bindings.

`<AttestationModal/>` is mounted inside `Play` (`src/components/blockpot/play/index.tsx`), gated by `usePlayerRegistration().attestationModalOpen`. It collects the user's DOB, jurisdiction, and TOS acknowledgment **before** the SIWE register call, and stores the attestation receipt via `@web3-storage/w3up-client`.

`<SelfExclusionRouteGate/>` is mounted inside `Play` to redirect a self-excluded player off the play surface.

The legacy `PinataStorageProvider` and `SettingsProvider` were removed in the v2 refactor.

## 8. Entry flow (PEA / CF / OF)

The most important v2 surface. Entries route through the LGO proxy contract (the Option B follow-up from the original v2 plan is shipped), which makes the on-chain leg a single atomic transaction.

**Total user cost:** `total = PEA + CF + OF` — read from chain via `LGO.entryQuote(lottery, amount)`.

| | | |
| --- | --- | --- |
| **PEA** | Protocol Entry Amount | `0.001 ETH` per entry, hardcoded in Lottery (`PEA_PER_ENTRY_WEI`). Flows to prize pool. |
| **CF** | Contributor Fee | 2% of PEA (`CF_BASIS_POINTS = 200n`). Routed by Lottery to DevCo on-chain. |
| **OF** | Operator Fee | Configured on-chain by the LGO owner (`LGO.operatorFeeBps`). Collected by the LGO contract and held until the operator withdraws. Read via `useOperatorFeeBps` / `useEntryQuote`. No env var. |

Constants for PEA/CF still live in `src/constants/protocol.ts` for display-only copy; the authoritative breakdown is `useEntryQuote`.

**Single-transaction on-chain flow** (`src/hooks/contracts/lottery/actions/useEnterDraw.ts`):
- **ETH path:** read `[total] = LGO.entryQuote(lottery, amount)`, then call `LGO.enter(lottery, roundIndex, amount, payoutInWeth)` with `{ value: total }`.
- **WETH path:** call `LGO.enterWeth(lottery, roundIndex, amount, payoutInWeth)` with no `msg.value`. The LGO pulls `total` WETH via `transferFrom` and unwraps internally. Allowance must be pre-approved against the **LGO address** (`useErc20WithAllowance(WETH, LGO)`), not the Lottery.

LGO forwards PEA+CF to the Lottery, routes OF into its own escrow, and is recorded as the operator for the round.

**Triple gate** (in order, each early-returns before any wallet prompt):
1. `useIsLGOWhitelisted()` — reads `ComplianceRegistry.isWhitelisted(LGO address)`. If false, `LGOWhitelistBanner` renders site-wide.
2. `useIsPlayerActive(account)` — reads `PlayerRegistry` for the connected wallet. Drives the in-EntryPanel "Register wallet" CTA via `usePlayerRegistration` (SIWE + attestation flow).
3. `evaluatePretxDeposit({ chainId, walletAddress, amountWei: total })` — off-chain pre-tx evaluator (gaming service). Mirrors the on-chain dual-track ladder so the user sees a clean error or `/verify` redirect before they spend gas. Decisions:
   - `allow: true` → proceed.
   - `allow: false, requiredAction: 'KYC_UPGRADE'` → `navigate({ to: '/verify', search: { tier: state.nextWagerThreshold.tier ?? 'T1' } })`. The wager-track tier is selected because entry is a wager-track action — the SoF/SoW gate set the user verifies into matches what the next-wager threshold demands.
   - `allow: false, anything else` → log and abort.

After the gate, before the wallet prompt, `recordEntryCadence()` is called so the Sybil correlator (gaming-service task 26) sees intent timing rather than wallet-UX delay.

**On-chain error fallback.** Even with the off-chain gate, on-chain `enter` can revert if a price feed goes stale or `KYCRegistry.isCompliant` flips between gate check and inclusion. `useEnterLottery` parses common revert reasons and surfaces user-facing toasts:
- `EurFeedStale` / `EthFeedStale` → "Price feed temporarily unavailable — try again shortly."
- `NotCompliant` → directs the user to complete missing KYC checks or contact MLRO support.

**Atomicity.** Because OF is collected inside the same transaction that mints the entries, the prior "step 1 succeeded / step 2 reverted / refund required" failure mode is gone. If any subcall reverts, the whole tx reverts and no fee is paid.

**Cost breakdown UI (`EntrySummary`):**
- Entry amount (PEA, to prize pool)
- Protocol fee (CF, 2%)
- Operator fee (OF, from chain)
- **Total**

## 8.5. Compliance & KYC (T0–T4 dual-track ladder)

The KYCRegistry owns the **active policy** — a versioned `KYCPolicy` describing each tier's required gates and EUR-minor thresholds. The frontend reads it with `useActivePolicy()` and combines it with per-player state to drive `usePlayerActivityState()`.

**Two independent tracks** (chain returns `tierOf = max(wagerTrackTier, winTrackTier)`; the frontend surfaces both):

- **Wager track** — `net ≤ tiers[i].wagerThreshold` where `net = max(0, lifetimeWageredEurMinor − lifetimeWonEurMinor)`. Wins restore headroom (task-49 switched this from gross to net). Drives `HeadroomBar` and the entry-time `nextWagerThreshold`.
- **Single-win track** — `largestSingleWinEurMinor ≤ tiers[i].singleWinThreshold`. Wins that advance the running max can flip the win-track tier independently. Top-tier policy carries `type(uint256).max` so a sufficiently large single win always crosses into T3+.

**`PlayerActivityState`** (exported from `src/hooks/player-summary/usePlayerActivityState.ts`):
```ts
{
  currentTier: 'T0' | 'T1' | 'T2' | 'T3' | 'T4'
  cumWageredEurMinor: number
  cumWonEurMinor: number
  netWageredEurMinor: number              // task-49: max(0, wagered − won)
  largestSingleWinEurMinor: number
  headroom: { wager: number }              // distance to current wager-track tier cap
  nextWagerThreshold:    { tier, eurMinor } | null
  nextSingleWinThreshold:{ tier, eurMinor } | null
  pendingClaimEurMinor: number             // escrowed beyond current tier's win allowance
}
```

Fed by:
- `useKycTier()` — chain tier ordinal
- `usePlayerGates()` — gate bitmap (`bigint`)
- `useLifetimeSnapshot()` — EUR-minor counters
- `useActivePolicy()` — policy tiers + thresholds

**Player gates** are a bitmap (`KYCRegistry.getPlayerGates`). Bits represent compliance checks the operator has granted: SumSub IDV pass, address verification, source-of-funds declaration, source-of-wealth declaration, etc. Each tier's `requiredGates` mask is a subset; `(playerGates & required) === required` is the on-chain compliance test. Gate-bit logic is centralized in `src/lib/kyc/gateBitmask.ts`.

**SumSub integration**: `src/components/kyc/SumsubSdkHost.tsx` wraps `@sumsub/websdk` and is mounted by `KycVerificationView` at `/verify`. The host fetches an applicant token with `useKycToken()`, which exchanges the SIWE Bearer for a per-player SumSub token from the gaming service.

**Display surfaces driven by `usePlayerActivityState`**:
- `HeadroomBar` (wager-track headroom + projected next threshold)
- `TierBadge`, `TierBreakdown`, `TierUpgradePrompt`
- `PrizePoolPreCommitBanner` (warns when an upcoming single-win could exceed the player's win-track allowance)
- `PendingCddBanner` (shows escrowed winnings beyond current tier's win allowance)

## 12.1. Sybil correlation signals

The Sybil correlation engine (gaming-service task 26) needs a stable per-device fingerprint plus a small bag of behavioral signals on every wallet-connected session that can lead to a deposit/withdrawal. Frontend pieces:

- `src/utilities/sybil/fingerprint.ts` — in-house fingerprint helper. Combines canvas, WebGL renderer, screen + DPI, hardware concurrency / device memory / platform / languages, font probe list, timezone, and user-agent into a single SHA-256 hex string. Raw components never leave the browser.
- `src/providers/SessionSignalProvider.tsx` — coalesces one POST per session per route to `/v1/session/signal` (fire-and-forget, no UI blocking) carrying `{ fingerprint_hash, behavioral }`. Behavioral payload is capped: session start, scroll/click counters, and at most the latest 64 entry-cadence timestamps. Exports `recordEntryCadence()`, called from `useEnterLottery` immediately before the wallet prompt.

We deliberately did **not** pull in `@fingerprintjs/fingerprintjs` — the Tier 0 EUR 500/wallet cap does not justify the supply-chain risk of a runtime dependency, and the backend correlator combines fingerprint with IP + funding-origin signals so the absolute uniqueness rate of the fingerprint is not load-bearing. If false positives on the MLRO queue become noisy, swap the helper out behind the same `computeDeviceFingerprint()` interface.

## 12.2. Player session & gaming service

The gaming service (`VITE_GAMING_SERVICE_URL`) is the LGO's automation backend. It owns SIWE token issuance, KYC orchestration, attestation receipts, the pre-tx deposit evaluator, and responsible-gaming state. The frontend integrates through:

- `src/api/gamingServiceClient.ts` — Bearer-token `fetch` wrapper. Holds the active token in a module-level snapshot so non-React helpers (e.g. `evaluatePretxDeposit`) can read it synchronously. Emits `subscribeSessionExpired()` events when the snapshot expires.
- `src/api/sessionSignal.ts` — `/v1/session/signal` POST helper (used by `SessionSignalProvider`).
- `src/api/SessionExpiryRecovery.tsx` — sibling component mounted inside `PlayerSessionProvider`; subscribes to expiry, clears the React session, and lets the SIWE flow re-prompt.
- `src/providers/PlayerSessionProvider.tsx` — stores the SIWE-derived `TokenSnapshot` ({ token, address, chainId, expiresAt }) and mirrors it into the gaming-service client.
- `src/hooks/contracts/player-registry/useSiweSignature.ts` — builds and signs the SIWE message and exchanges it for a Bearer token.

When `VITE_GAMING_SERVICE_URL` is unset, authenticated calls throw `ApiError({ code: NO_SERVICE_URL })`. The register CTA short-circuits to a disabled state (`playerRegistration.serviceConfigured === false`).

## 15. Extension points

Map of where new code plugs in — not a playbook.

- **Add a contract.** Extend `ContractName` enum, add to `getContractAddress` switch, add a key to every `src/constants/contract-addresses/*.ts`, add the entry to the owning repo's `cli/abis.toml` (either `../unipot-contracts` or `../blockpot-contracts`), then `bun sync-abis` + `bun sync-addresses`.
- **Add a read hook.** Create `src/hooks/contracts/<contract-name>/useXRead.ts` wrapping `useReadContract`; build domain hooks on top.
- **Add a write hook.** Wrap with `useTrackedContractWrite`; lifecycle and toasts flow through `TransactionsProvider` automatically.
- **Add a provider.** Insert into `__root.tsx` respecting dependencies: QueryClient must wrap query consumers; Web3 must wrap chain/account readers; PlayerSession must wrap any consumer of the gaming-service token; BlockpotEvents must wrap BlockpotProvider.
- **Add a route.** Drop a file in `src/routes/`; let `TanStackRouterVite` regenerate `routeTree.gen.ts`. Use `validateSearch` for any user-controllable navigation target (see `/verify` for the whitelisting pattern).
- **Add a feature UI.** `src/components/blockpot/<feature>/` with co-located `*.story.tsx`. Cross-cutting concerns (KYC, responsible-gaming, onboarding) live at `src/components/<concern>/` instead. Design system first, `ui/` second, `core/` primitives last.
- **Add a type.** Extend `src/types/<domain>/`; use `abitype` when deriving from ABIs.
- **Add a query.** Follow `['<domain>', selectedGame?, chainId, userAddress?, ...]`; include `useEventsBlockNumber` output in the key for event-driven freshness.
- **Add a contract event subscription.** Add a new watcher in `BlockpotEventsProvider`, then a `useTriggerOnChanged` that invalidates the matching query keys.
- **Change persisted shape.** Bump the `v6` buster in `QueryClientProvider`.
